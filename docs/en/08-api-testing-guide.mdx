## Prerequisites and scope

The Azure full-origin provides DVGA, RESTaurant, VAmPI and crAPI. The independent AWS module provides Juice
Shop only. Use generated application URLs and [native fixture workflows](../application-workflows/). Operator
inputs `ORIGIN_BASE`, `EVIDENCE_DIR` and catalog configuration remain private. Acquire real native
authentication for the same actor; missing sessions or tokens fail prerequisites.

## Published API entry points

| Application | Definition or UI | API route |
| --- | --- | --- |
| VAmPI | `/vampi/openapi.json` | `/vampi/users/v1`, `/vampi/users/v1/login` |
| DVGA | `/dvga/` | `/dvga/graphql` |
| RESTaurant | Swagger `/restaurant/`, ReDoc `/restaurant/redoc`, definition `/restaurant/openapi.json` | Use paths from the actual definition |
| crAPI | `/crapi/`, captured mail `/crapi/mailhog/` | `/crapi/identity/`, `/crapi/community/`, `/crapi/workshop/` |

For a read-only definition check on the reviewed origin:

```bash
curl --fail "$ORIGIN_BASE/vampi/openapi.json"
curl --fail "$ORIGIN_BASE/restaurant/openapi.json"
```

VAmPI responses are JSON. GraphQL uses valid JSON documents and explicit operation/variable contracts. RESTaurant login is form-encoded where the actual API requires it. crAPI reset requires the exact actor's real emailed OTP; welcome VIN/pincode establishes vehicle registration. See [Application workflows](../application-workflows/) for cleanup and JWT repair.

Use [catalog operation](https://f5-sales-demo.github.io/traffic-generator/en/06-runner/) for supervised installed execution with one shared pacing boundary. Native FFmpeg/FFprobe encode and validate real synthetic video; header bytes are not a video fixture. Mutation scenarios require baseline capture, native postconditions and exact restoration.

## Verify outcomes and clean up

Preserve intended method/path/payload/action evidence separately from fixture setup and filler. Native
response/report contracts establish application behavior; process cleanup must be observed. Classify expected
application rejection, prerequisite failure, tool error, timeout, transport failure and mitigation candidates
separately. Correlate the applicable WAAP control in a separate receipt before claiming mitigation. CSD
activity is display-only in the WAAP showcase.

A complete dispatch contract, successful tool exit or focused pass cannot qualify missing functional contracts or the full catalog. Complete [workflow/browser verification](../05-verify/), fixture recovery, current-source full passes and the showcase clean rebuild remain required.
